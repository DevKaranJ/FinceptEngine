# Strategy Authoring Guide & Validation Gatekeeper Specification

**Project Name:** Self-Improving Multi-Paradigm Quantitative Trading Engine  
**Purpose:** Standardizes how indicators, signals, and strategies are written and how candidate upgrades (`V2`) are mathematically validated.

---

## 1. The Lego-Block Strategy Pattern (`Indicators` $\rightarrow$ `Signals` $\rightarrow$ `Strategies`)

Every strategy in the system—whether written by you from an online research paper or generated by the AI Coding Agent—must follow a strict 3-step separation so components remain 100% reusable.

### Step 1: Pure Math Indicator (`indicators/*.py`)
- **Rule**: Takes a pandas DataFrame (`open`, `high`, `low`, `close`, `volume`) and parameters; returns a numeric Series or dictionary of levels. Never contains `BUY`/`SELL` logic.
- **Anti-Look-Ahead Rule**: Indicators must only use historical and current row data (`iloc[:t]`). Using future data (`shift(-1)` or whole-series unanchored `.mean()`) is strictly forbidden.

### Step 2: Reusable Signal Condition (`signals/*.py`)
- **Rule**: Takes the latest bar/feature row and returns a boolean (`True` or `False`).
- **Examples**:
  - `is_ema_bull_trend(row)` $\rightarrow$ `row['close'] > row['ema_fast'] > row['ema_slow']`
  - `is_atr_expanding(row)` $\rightarrow$ `row['atr_14'] > row['atr_sma_50'] * 1.15`
  - `is_inside_bullish_fvg(row)` $\rightarrow$ `row['fvg_bull_bottom'] <= row['low'] <= row['fvg_bull_top']`
  - `is_above_vwap(row)` $\rightarrow$ `row['close'] >= row['vwap']`

### Step 3: Versioned Strategy Recipe (`strategies/base_strategy.py`)
Every strategy inherits from `BaseStrategy` and defines its metadata, parameters (for heatmap sensitivity testing), and `evaluate()` rule:

```python
from strategies.base_strategy import BaseStrategy
from signals.technical_signals import is_ema_bull_cross, is_atr_above_threshold

class EmaBreakoutV2(BaseStrategy):
    strategy_id = "EMA_BREAKOUT_V2"
    parent_strategy_id = "EMA_BREAKOUT_V1"
    paradigm_tags = ["TECHNICAL", "VOLATILITY_FILTER"]

    # Tunable parameters automatically tested by the Parameter Sensitivity Heatmap
    default_params = {
        "ema_fast_len": 20,
        "ema_slow_len": 50,
        "atr_len": 14,
        "atr_mult_threshold": 1.25,
        "sl_atr_mult": 1.5,
        "tp_rr_ratio": 2.0
    }

    def evaluate(self, df_features, current_idx):
        row = df_features.iloc[current_idx]

        # 1. Filter Gate (Added by AI Hypothesis Agent in V2 to fix low-volatility losses)
        if not is_atr_above_threshold(row, self.params["atr_mult_threshold"]):
            return None

        # 2. Entry Trigger
        if is_ema_bull_cross(df_features, current_idx, self.params["ema_fast_len"], self.params["ema_slow_len"]):
            entry = float(row["close"])
            atr = float(row["atr_14"])
            sl = entry - (self.params["sl_atr_mult"] * atr)
            risk = entry - sl
            tp1 = entry + (risk * self.params["tp_rr_ratio"])

            return self.build_signal(
                row=row,
                direction="LONG",
                entry_price=entry,
                stop_loss_raw=sl,
                target_1_raw=tp1,
                active_signals=["EMA_BULL_CROSS", "ATR_VOLATILITY_FILTER"]
            )
        return None
```

## 2. Evaluation Engine Mathematical Formulas (`evaluation/analyzer.py`)

Given a set of closed trades $i \in \{1, \dots, N\}$ with net PnL $P_i$ and realized R-multiple $R_i = \frac{P_i}{\text{Initial Risk}_i}$:

1. **Win Rate ($W$)**:
   $$W = \frac{\text{Count}(P_i > 0)}{N}$$
2. **Profit Factor ($\text{PF}$)**:
   $$\text{PF} = \frac{\sum_{P_i > 0} P_i}{\left|\sum_{P_i < 0} P_i\right|}$$
3. **Mathematical Expectancy ($E_R$)**:
   $$E_R = \left(W \times \overline{R}_{\text{win}}\right) - \left((1 - W) \times |\overline{R}_{\text{loss}}|\right)$$
4. **Maximum Adverse & Favorable Excursion (`MAE` & `MFE`)**:
   - For a `LONG` trade open during interval $[t_{\text{in}}, t_{\text{out}}]$ with initial risk $\Delta_{\text{risk}} = P_{\text{entry}} - P_{\text{SL}}$:
     $$\text{MAE}_R = \frac{\min_{t \in [t_{\text{in}}, t_{\text{out}}]} (\text{Low}_t) - P_{\text{entry}}}{\Delta_{\text{risk}}}, \quad \text{MFE}_R = \frac{\max_{t \in [t_{\text{in}}, t_{\text{out}}]} (\text{High}_t) - P_{\text{entry}}}{\Delta_{\text{risk}}}$$
   - For a `SHORT` trade:
     $$\text{MAE}_R = \frac{P_{\text{entry}} - \max_{t \in [t_{\text{in}}, t_{\text{out}}]} (\text{High}_t)}{\Delta_{\text{risk}}}, \quad \text{MFE}_R = \frac{P_{\text{entry}} - \min_{t \in [t_{\text{in}}, t_{\text{out}}]} (\text{Low}_t)}{\Delta_{\text{risk}}}$$

## 3. Independent Validation Gatekeeper Rules (`validation/gatekeeper.py`)

**Core Rule: Never let AI approve its own strategy.**  
When a candidate strategy (`V2`) is submitted for promotion over Baseline (`V1`), `gatekeeper.py` runs 4 deterministic tests. **All 4 must return `PASS`** for `V2` to be promoted:

| Test # | Validation Check | Exact Mathematical Pass Criteria | Why It Protects You |
| :--- | :--- | :--- | :--- |
| **Test 1** | **Out-of-Sample (OOS) Unseen Data Split** | Dataset is split chronologically: first $70\%$ In-Sample (Train) and final $30\%$ Out-of-Sample (Unseen).<br>• $\text{PF}_{\text{OOS}}(V_2) \ge 1.25$<br>• $E_{R,\text{OOS}}(V_2) > E_{R,\text{OOS}}(V_1)$<br>• $\text{MaxDD}_{\text{OOS}}(V_2) \le \text{MaxDD}_{\text{OOS}}(V_1)$ | Prevents the AI from memorizing historical noise that fails on future unseen candles. |
| **Test 2** | **Rolling Walk-Forward Analysis (WFA)** | Evaluates $K = 5$ rolling chronological windows (Train window $W_{\text{train}}$ followed immediately by Test window $W_{\text{test}}$).<br>• At least $4$ of $5$ ($\ge 80\%$) unseen test windows must have net positive return ($E_R > 0$). | Verifies that the strategy performs consistently across different months and market cycles. |
| **Test 3** | **Parameter Sensitivity Heatmap ($5 \times 5$ Grid)** | Perturbs the strategy's top 2 numerical parameters by $\{-20\%, -10\%, 0\%, +10\%, +20\%\}$ (25 grid cells).<br>• At least $20$ of $25$ ($\ge 80\%$) grid cells must maintain $\text{PF} > 1.10$. | Detects fragile "curve-fitted" parameter spikes. If changing EMA from `20` to `22` ruins the strategy, it is rejected. |
| **Test 4** | **Execution Cost & Slippage Stress Test** | Re-runs the Out-of-Sample backtest with $1.5\times$ baseline slippage and full taker commissions.<br>• Stressed $\text{PF}_{\text{OOS}} \ge 1.15$ and net Expectancy $E_R \ge +0.12R$. | Ensures the strategy's edge survives real-world spread widening and exchange fees. |
